# AGENTS.md — CDR по критической энергии NICA

## Главное правило

Один шаг = одна issue = одна задача агента = один PR.
Следующий шаг начинается только после того, как Bell принял предыдущий.

## Порядок

Разбор работ (по issue на работу), затем введение, затем главы по очереди.
Проблема, найденная при написании главы, — отдельная issue с меткой
`cdr:problem`. Она рассматривается в главе.

Issue открываются постепенно: сначала подготовка проекта и разборы;
введение, главы и проблемы — когда до них доходит очередь.

## Как шаг превращается в PR

1. Берём открытую issue.
2. Ветка от `main`: `<тип>/<кратко>`, например `docs/cdr-ch01-introduction`.
3. Пишем LaTeX в `CDR/latex`; документ собирается без ошибок
   и без неразрешённых `\ref` и `\cite`.
4. PR с `Closes #N`. В описании: что написано, откуда числа, что осталось открытым.
5. Bell читает и принимает, squash-merge в `main`.

Язык issue, PR, коммитов и текста — русский. Коммиты: `docs(cdr): …`, `fix(cdr): …`.

## Границы

- Меняем только `CDR/` (и корневой README в issue подготовки проекта).
  Остальные папки репозитория не трогаем.
- В рабочем дереве NICA много чужих изменений. Индексируем только свои пути,
  `git add -A` запрещён.
- Без force-push, без переписывания истории `main`.

## Документ

- Класс REVTeX 4.2, русский язык. Безличная форма («рассмотрены», не «я рассматривал»).
- Рисунки берём из статей и диссертации, копируем в `latex/figures`
  с префиксом главы, не перерисовываем. Источник рисунка — в issue главы.
- Таблицы — для параметров, сравнений и сводок.
- Библиография: DOI обязателен, ключи по INSPIRE; если работы там нет —
  `% Not in INSPIRE` и понятный ключ. Русский оригинал и перевод — одна запись.

## Текст

- Каждое число — со ссылкой на работу или на расчёт в главе.
- Допущения пишем явно. Принятые, а не выведенные величины помечаем.
- Формулу, которой нет в источниках, помечаем и проверяем отдельно.
- Естественный русский язык, короткие предложения.
- Каждый символ определяется при первом появлении.
- Нигде не упоминаем ИИ.
